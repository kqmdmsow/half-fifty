# 수집 후보 (staging) — 골든셋이 아니다

이 디렉터리의 CSV는 `agent/collect_cases.py`가 법제처 OPEN API에서 자동으로
긁어온 **검수 대기 후보**다. 골든셋(`data/real_clause_labels*.csv`)이 아니다.

## 왜 자동으로 골든셋에 넣지 않는가

우리 데이터 원칙은 "원문 정독 → 독립 적대적 검수 통과분만 반영"이고, 3라운드
누적 통과율이 55~60%였다. 자동 수집이 그 절차를 대체하면 골든셋의 신뢰도가
무너지고, **그 위에서 잰 모든 수치가 의미를 잃는다.** 자동화가 줄이는 것은
찾는 수고이지 검수가 아니다.

## 각 열의 뜻

| 열 | 내용 | 신뢰도 |
|---|---|---|
| `case_no`·`case_name`·`doc_url` | 출처 추적용 | 그대로 신뢰 가능 |
| `opinion` | 공정위가 내린 판정 (무효/부분 무효/유효) | `opinion_source=명시`면 원문 그대로 |
| `opinion_source` | `명시`(원문에 "심사의견: 무효") 또는 `조문인용 추론`("약관법 제9조에 해당된다"에서 유추) | 추론은 검수 필수 |
| `gold_risk_level_candidate` | 판정 → 우리 3단계 매핑 후보 | 후보일 뿐 |
| `articles` | 인용된 약관규제법 조문 | 그대로 신뢰 가능 |
| `gold_risk_type_candidates` | 조문 → 위험 유형 10종 매핑 후보. 한 조문이 여러 유형에 걸리면 나열된다 | **검수자가 하나를 고를 것** |
| `rationale` | 결정문의 판단 근거 서술 (최대 1500자) | 원문 |
| **`clause_text`** | **비어 있다** | **검수자가 채워야 한다** |
| `review_status` | `미검수` | |

## 가장 큰 한계 — 조항 원문이 없다

결정문의 "가. 약관조항" 항목은 원본에서 **표로 조판**돼 있어 API의 XML 응답에서
탈락한다(HTML 형식은 JavaScript 껍데기만 온다). 즉 이 파이프라인은
**"어떤 조항이 왜 불공정한가"는 주지만 "그 조항의 원문 문구"는 주지 못한다.**

검수자는 `doc_url`을 열어 원문 표에서 조항 문구를 옮겨 적어야 한다.
`rationale`에 조항 내용이 인용된 경우도 많아 그것이 단서가 된다.

## 검수 후 이동 절차

1. `doc_url`로 원문을 열고 조항 문구를 `clause_text`에 채운다.
2. `gold_risk_level_candidate`가 판단 근거와 맞는지 확인한다.
   특히 `opinion_source=조문인용 추론`은 반드시 원문으로 확인한다.
3. `gold_risk_type_candidates` 중 하나를 확정한다.
4. **다른 사람이** 원문을 재대조하며 반박을 시도한다(독립 적대적 검수).
5. 통과분만 `data/real_clause_labels*.csv`로 옮기고 `split`을 배정한다.
   - **test 배정은 신중히.** held-out 원칙상 test에 들어간 조항은 개선 확정 시
     1회만 측정한다. 튜닝에 쓸 것은 train/val로 보낸다.
   - 같은 사건에서 나온 조항은 같은 split에 넣는다(누수 차단).
6. 기각한 것은 사유와 함께 기록한다 — 지금까지 해 온 방식 그대로다.

## ⚠️ 표본 편향 — 이 소스만으로는 골든셋을 채울 수 없다

**실측: 수집한 297건 중 295건(99%)이 '위험' 후보다.**

당연한 결과다. 사건명 `불공정약관조항`으로 검색하면 공정위가 **불공정하다고
판단한 건만** 모인다. 공정위는 "이 조항은 괜찮다"는 심결을 따로 내지 않는다.

이 상태로 골든셋에 넣으면 **리콜은 부풀고 정밀도는 잴 수 없게 된다.** 안전
표본이 없으면 오탐을 측정할 방법이 사라지기 때문이다. 현재 골든셋은
위험 54 / 안전 57로 균형이 잡혀 있는데, 그 균형이 깨진다.

### 판례 경로로 안전 표본을 모아 봤고, 부족하다는 것이 확인됐다

`--target prec --verdict safe`를 만들어 판례에서 법원이 "부당하다고 볼 수 없다"고
판단한 조항을 뽑았다. 법원까지 갔는데 유효 판정을 받은 조항은
**"위험해 보이지만 유효한 경계 사례"**라 오탐 측정에 가장 값진 표본이다.

**실측 결과: 8개 질의 · 판례 320건에서 안전 후보 12건.** 위험 267건 대비 여전히
크게 모자란다. 이유는 구조적이다 — 법원까지 가는 조항은 대개 다투어진 조항이고,
유효 판정이 나도 판결문이 그 결론을 조항 인용 근처에 적지 않는 경우가 많다
(판정 미상 97건).

**따라서 안전 표본은 자동 수집으로 채울 수 없다.** 다음 경로를 써야 한다.
- 정부·공정위 **표준계약서** — 이미 `data/normal_contracts/`에 5문서 94조항이 있다
- **판례에서 "부당하다고 볼 수 없다"고 판단한 조항** — `--target prec`로 수집한 뒤
  판결 이유에서 유효 판정만 골라낸다
- 공정위 심결 안에서도 `opinion=유효`인 조항 (드물지만 있다)

## 판정 근거 방식이 반반이다

| 방식 | 건수 | 뜻 |
|---|---|---|
| `명시` | 148 | 원문에 "심사의견: 무효"가 적혀 있다 |
| `조문인용 추론` | 149 | 판정 라벨 없이 "약관법 제9조에 해당된다"로만 끝나 유추했다 |

**추론분 149건은 반드시 원문 확인이 필요하다.** 전부 '위험'으로 찍혀 있는데,
추론 규칙이 그렇게 되어 있어서지 공정위가 그렇게 판단했다는 뜻이 아니다.

## 위험 유형 후보는 순서 아티팩트를 포함한다

`부당한 비용·세금 전가`가 134건으로 1순위인데, 이는 약관규제법 §6이 여러 유형에
걸쳐 있고 매핑 목록에서 그 유형이 맨 앞에 있기 때문이다. **첫 번째 후보를 그대로
채택하면 안 된다.** `gold_risk_type_candidates`의 `|` 구분 목록에서 검수자가
근거 서술을 읽고 골라야 한다.

## 지금 우선 필요한 유형

`docs/eval_recall_recovery_investigation.md`에 적힌 대로,
**"법령·판례를 참조만 하고 구체 요율을 적지 않은 수수료·이자 조항"**이
train/val에 한 건도 없다. 그 유형이 없어서 공식 Test의 FN을 고치지 못하고 있다.
수집 시 이 유형을 우선 찾을 것.

## 검수 보조 도구 (`agent/review_assist.py`)

공정위 심결 후보는 `clause_text`가 비어 있다(위 "가장 큰 한계" 참조). 297건의
원문을 하나씩 열어 표에서 문구를 옮겨 적는 것은 자동화 이전과 다를 바 없는
노동이라, 판단 근거 서술에서 조항 문구를 뽑아 두는 보조 도구를 만들었다.

```
cd agent && python review_assist.py ../data/staging/candidates_ftc_불공정약관조항.csv
```

추가되는 열:

| 열 | 내용 |
|---|---|
| `clause_text_candidate` | 근거 서술에서 뽑은 조항 문구 **후보** |
| `confidence` | 높음(명시 인용) / 보통(서술 그대로) / 낮음 |
| `assist_note` | 검수자에게 남기는 메모 |

**이 도구는 `clause_text`를 채우지 않고 `review_status`도 바꾸지 않는다.**
검수자가 원문과 대조해 확정하는 절차는 그대로다.

### 창작 방지 장치

LLM이 낸 문구가 근거 서술에 **글자 그대로 없으면 폐기**하고 `assist_note`에
"창작 의심"으로 기록한다. 검수자가 지어낸 문장을 원문이라 믿고 넘기면 골든셋이
조용히 오염되는데, 그것이 자동화가 만들 수 있는 최악의 사고다.

실측(12건 표본): 성공 4 / 인용없음 7 / **폐기 1**. 폐기 1건은 실제로 LLM이
지어낸 문구였고 대조 검증이 잡아냈다.

## 판례 경로 (`--target prec`)

공정위 심결이 못 주는 조항 원문을 판례가 준다. 법원은 판단 근거를 대기 위해
**조항을 본문에 그대로 인용**하기 때문이다.

```
cd agent && python collect_cases.py --target prec --query 위약금약정 --section 2
```

주의: 판결문에는 법령 인용("민법 제741조는 …라고 정하고 있다")과 계약 조항
인용("이 사건 이용약관 제23조는 …")이 같은 문형으로 섞여 있다. 추출기가
앵커와 법령 배제 목록으로 구분하고, 법원의 판단 서술("따라서 …인정된다")이
섞인 것도 걸러낸다. 그래도 오추출이 있을 수 있으니 `context` 열로 확인할 것.

판례 경로는 조항별 판정이 명시되지 않으므로 `gold_risk_level_candidate`가
비어 있다. 판정은 검수자가 판결 이유를 읽고 정해야 한다.
