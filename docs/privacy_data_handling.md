# 개인정보·업로드 데이터 처리 방식 (자문 §7 반영 현황)

계약서에는 이름·주소·계좌 등 개인정보가 포함될 수 있다. 현재 구현이 데이터를
어떻게 다루는지와 남은 과제를 기록한다. (최종보고서·해커톤 기획서 §7 재료)

## 현재 구현 (2026-08-18)

| 항목 | 상태 |
|---|---|
| 요청 경로 | **모든 요청 백엔드 경유** — 텍스트·PDF·이미지 모두 프론트→백엔드→에이전트. 프론트→에이전트 직통 제거됨 |
| 파일 검사 | 백엔드·에이전트 양쪽에서 매직 바이트(%PDF-, jpg/png/webp 시그니처)·크기(10MB) 검증 — Content-Type 위조 방어. 에이전트 자체 검증은 render.yaml상 에이전트가 public web service라 백엔드를 거치지 않는 직접 호출도 방어하기 위함(#77) |
| 개인정보 마스킹 | **텍스트 경로는 파이프라인 진입 시 마스킹 완료** — 주민등록번호·전화번호·이메일·카드번호는 항상, 계좌번호는 키워드 앵커 조건부로 정규식 마스킹 후에만 LLM에 전달 (`masking.py`, 유닛테스트 12건) |
| 저장 | **업로드 파일·추출 텍스트를 어디에도 저장하지 않음** — 백엔드·에이전트 모두 메모리에서만 처리 후 응답과 함께 소멸. 보존기간 = 0 |
| 외부 전송 (텍스트) | 마스킹된 조항 텍스트가 LLM API(Anthropic)로 전송됨 — Anthropic API는 기본적으로 입력을 학습에 사용하지 않음(zero data retention 옵션 아님, 표준 보존 정책 적용) |
| **외부 전송 (OCR, 알려진 한계)** | **사진·스캔본 업로드 시 원본 파일이 마스킹 없이 Upstage Document Parse API로 전송된다.** 텍스트 마스킹은 OCR로 추출된 *텍스트*에만 적용되며, 이미지 자체(주민번호·서명·주소가 시각적으로 포함될 수 있음)는 대상이 아니다. 목적: 레이아웃·표 구조 인식(계약서 별표·수수료율 표 보존, 자문 §2). 통제: 요청-응답 메모리 중계만(무저장), 사용자 업로드 시 고지 문구 예정(#77 백로그) |
| 로그 | 조항 원문·파일명을 서버 로그에 남기지 않음. 접근 로그는 메서드·경로·상태코드·소요시간·요청 크기만 기록 (backend AccessLogFilter, agent access 미들웨어 — #80) |
