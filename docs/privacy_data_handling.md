# 개인정보·업로드 데이터 처리 방식 (자문 §7 반영 현황)

계약서에는 이름·주소·계좌 등 개인정보가 포함될 수 있다. 현재 구현이 데이터를
어떻게 다루는지와 남은 과제를 기록한다. (최종보고서·해커톤 기획서 §7 재료)

## 현재 구현 (2026-08-12)

| 항목 | 상태 |
|---|---|
| 요청 경로 | **모든 요청 백엔드 경유** — 텍스트·PDF 모두 프론트→백엔드→에이전트. 프론트→에이전트 직통 제거됨 |
| 파일 검사 | 백엔드에서 매직 바이트(%PDF-)·크기(10MB) 검증 — Content-Type 위조 방어 |
| 저장 | **업로드 파일·추출 텍스트를 어디에도 저장하지 않음** — 백엔드·에이전트 모두 메모리에서만 처리 후 응답과 함께 소멸. 보존기간 = 0 |
| 외부 전송 | 조항 텍스트가 LLM API(Anthropic)로 전송됨 — Anthropic API는 기본적으로 입력을 학습에 사용하지 않음(zero data retention 옵션 아님, 표준 보존 정책 적용) |
| 로그 | 조항 원문을 서버 로그에 남기지 않음 (분석 실패 시 오류 메시지만) |

## 남은 과제 (우선순위순)

1. **개인정보 마스킹**: LLM 전송 전 이름·주민번호·계좌·전화번호 패턴을
   정규식으로 마스킹 (조항 판정에 개인 식별자는 불필요 → 손실 없음)
2. 오류·접근 기록 관리(백엔드 로깅 표준화), UI 법적 고지 문구(민찬 배정 항목)와 연결
3. 이력 저장 기능을 만들게 될 경우: 동의·보존기간·삭제 API를 함께 설계
   (저장 없음이 기본값 — 저장은 명시적 기능 추가로만)
