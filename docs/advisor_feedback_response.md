## B. 신규 작업 (우선순위순)

단계 전체를 무효화하므로 RAG 등 신규 기능보다 선행. **잔여 3건은 #79로 이관**
(2026-08-19 상태 확인).
- [x] 조의N(제9조의2 등) 분리 버그 수정 — `agent/src/nodes/parser.py` `_ARTICLE_PATTERN`
- [ ] 별표·부칙·특약·표 독립 청크 분리 — 미완. 현재 별표가 앞 조항 꼬리에
      ~2,100자 덩어리로 붙어 생존(살아남지만 조항 단위 판정 입도가 무너짐) — #79 항목 1
- [x] 조항 번호-본문 연결 정확성 — 위 조의N 수정과 동일 근거로 완료

- [ ] 불완전 문서를 "검토 필요"로 명시 처리 — 미완. 현재는 경고만 붙이고 그대로

### B4. Judge 피드백 기반 조건 분기 — LangGraph 정당화
"재생성 = 동일 Analysis 단순 반복"은 우연을 기대하는 구조라는 지적 수용.
- [x] aspect별 재생성 대상 분기: clarity만 미달 & risk_coverage·faithfulness가
      임계값보다 확실히 위일 때만 Persona만 재실행, 그 외는 Analysis 전체
      재실행 — `agent/src/graph.py` `_route_retry_target`(PR #87). 최초
      시도(#35)가 마진 없이 단축을 허용했다가 데모 재측정에서 오분류가
      새어나가는 게 실측돼 거부됐고(FP 3→7), PR #87에서 마진 규칙을 추가해
      안전성 검증 후 재설계·머지함
- [ ] 재생성 프롬프트에 Judge rationale 주입 — 시도했으나 되돌림. PR #87과
      함께 구현해 측정했는데 안전한 조항(contract_05)에서 FP가 1→5~6으로
      늘어나는 부작용이 확인돼(모델이 채점자 지적에 과잉반응하는 것으로 추정)
      제외 — 이슈 #88에서 문구·주입 방식 재설계 진행 중
- 계획 중인 법령 인용 검증(법제처 API)과 결합 시 "근거 부족→검증 단계" 분기 완성

### B5. 페르소나 효과 검증 재설계 (사람 평가 트랙에 흡수)
- 위험 탐지 점수가 아니라 **이해도**로 측정: 동일 조항의 기본/고령층 설명을
  각 그룹에 제시 → 이해도 문항 정답률·소요 시간·만족도 비교

### B6. 출력 톤 조정 (사업화 포지셔닝)
- "불공정 판정" 단정 → "주의가 필요한 이유 + 근거 문구 + 상담 시 확인 질문"
  구조는 이미 출력 스키마와 일치. UI 문구에서 단정 표현만 점검
- 포지셔닝: 일반 소비자 대상 법률판단이 아니라 **상담 전 보조도구**
  (금융복지상담센터 등) — 최종보고서·해커톤 기획서에 반영

## C. 자문 결론의 우선순위 vs 우리 계획

자문 권장: 범위 명확화 → Parser → 프롬프트 공개 → 평가체계 → LangGraph 검증
→ RAG·개인정보. 이 중 범위·프롬프트·평가체계는 상당 부분 완료 상태이므로,
실행 순서는 **B1(Parser) → B2(게이트) → B3(API 구조) → B4(조건 분기)**.
B1·B2의 규칙 검사는 크레딧 불요.
