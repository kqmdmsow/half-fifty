## B. 신규 작업 (우선순위순)

### B1. Parser 강화 — 자문 최우선 지적, 정당함
별표 누락·제9조의2 병합은 중간보고서에 기록된 실제 버그. 입력 손실은 이후
단계 전체를 무효화하므로 RAG 등 신규 기능보다 선행.
- [ ] 하위 항목(조의2, 각호, 별표·부칙·특약·표) 보존 분리
- [ ] 조항 번호-본문 연결 정확성
- [ ] 추출 실패·누락 가능성 사용자 고지, 불완전 문서는 "검토 필요" 처리
- [ ] 실물 금융계약서 기반 회귀 테스트 확대 (현 14건 → 실물 다양성 반영)

### B2. Judge 게이트 구조 개선
- [ ] **치명 항목 필수 조건**: faithfulness(원문 왜곡·허위 근거) 미달 시 평균
      무관 실패 처리 — 현 평균 3.5 게이트는 치명 결함을 평균으로 은폐 가능
- [ ] **인용 근거 원문 존재 규칙 검사**(코드, LLM 불요): risk_evidence의 인용이
      조항 원문에 실제 존재하는지 문자열 검증
- [ ] 게이트 안정성 실험: 동일 출력 5~10회 채점 → 통과/재생성 **결정 일치율**
      측정 (크레딧 충전 후)

### B3. 개인정보·API 구조 (해커톤 배포와 병합)
- [ ] **PDF 직통 제거**: 현재 프론트→에이전트 직접 전송 구조를 백엔드 경유로
      통합 (자문 지적이 실제 구조와 일치)
- [ ] 외부 LLM 전송 전 개인정보 마스킹, 업로드 파일 보존기간·삭제 정책,
      파일 형식·용량 검사, 오류·접근 기록
- 금융보안원 주최 해커톤 심사 어필 요소로 전환 가능

### B4. Judge 피드백 기반 조건 분기 — LangGraph 정당화
"재생성 = 동일 Analysis 단순 반복"은 우연을 기대하는 구조라는 지적 수용.
- [ ] 낮은 aspect별 재생성 대상 분기: faithfulness→Analysis(원문 재강조),
      clarity→Persona만 재실행, risk_coverage→Analysis
- [ ] 재생성 프롬프트에 Judge rationale 주입 (현재는 미주입)
- 계획 중인 법령 인용 검증(법제처 API)과 결합 시 "근거 부족→검증 단계" 분기 완성

### B5. 페르소나 효과 검증 재설계 (사람 평가 트랙에 흡수)
- 위험 탐지 점수가 아니라 **이해도**로 측정: 동일 조항의 기본/고령층 설명을
  각 그룹에 제시 → 이해도 문항 정답률·소요 시간·만족도 비교

### B6. 출력 톤 조정 (사업화 포지셔닝)
- "불공정 판정" 단정 → "주의가 필요한 이유 + 근거 문구 + 상담 시 확인 질문"
  구조는 이미 출력 스키마와 일치. UI 문구에서 단정 표현만 점검
- 포지셔닝: 일반 소비자 대상 법률판단이 아니라 **상담 전 보조도구**
  (금융복지상담센터 등) — 최종보고서·해커톤 기획서에 반영

## C. 자문 결론의 우선순위 vs 우리 계획

자문 권장: 범위 명확화 → Parser → 프롬프트 공개 → 평가체계 → LangGraph 검증
→ RAG·개인정보. 이 중 범위·프롬프트·평가체계는 상당 부분 완료 상태이므로,
실행 순서는 **B1(Parser) → B2(게이트) → B3(API 구조) → B4(조건 분기)**.
B1·B2의 규칙 검사는 크레딧 불요.
