## [2026-08-06 추가] split 배정 원칙 — train/val용 경계 안전 확보가 다음 스프린트 최우선

1차 스프린트의 검수 통과분(임대차 확장 14 + 금융 8행)은 **전부 test 성격**으로
배정됐다. 그 결과 확장 세트 1회 측정에서 드러난 개선 목표(경계 안전 오탐 —
"위험 문구 패턴 과잉 반응")를 공략할 때 **보고 고쳐도 되는 사례가 train/val에
사실상 없다**: 실측 기준 train 3건/val 1건뿐이고 경계 안전 유형은 0건이다.
(test의 경계 안전을 보고 프롬프트를 고치면 오염 — 절대 금지)

다음 수집분부터의 배정 원칙:
- **경계 안전 신규 확보분은 train:val:test ≈ 2:1:2로 분배** (test 몰아주기 금지).
  목표: train용 경계 안전 4건+, val용 2건+ — 이게 확보돼야 오탐 공략 사이클이
  합법적으로 돈다.
- 위험 유형 보충분(위약금·수수료)도 각 1건 이상은 train/val에 배정.
- 배정은 **수집 시점에 확정하고 CSV의 split 컬럼에 즉시 기록** — 사후 재배정은
  "성적 좋은 쪽을 test로 고르는" 선택 편향 여지가 있으므로 금지.
- 같은 사건·같은 문서에서 나온 조항은 반드시 같은 split에 (누수 방지).

## 라벨 기준 (기존과 동일, 재확인)

- **A등급**: 정부·법원이 실제로 판정한 사례(hldcc 조정, LBox 판결)만. 판정 근거 문장을 출처 필드에 기록.
- **C등급**: AI Hub 등 자체 판단 라벨 — 별도 등급 컬럼 유지, A등급 집계에 섞지 않는다.
- risk_level·risk_type은 판정문 원문 근거로만 부여. 애매하면 버린다(모호 라벨 1건이 통계 전체를 오염).

## 앵커쌍 제작 기준 (이번에 발견된 결함의 재발 방지 — 필수 준수)

2026-08-05 교차검증에서 확장분 34쌍 전체가 아래 기준 위반으로 재작성됐다
(`docs/eval_pairwise_judge_family_analysis.md`). 신규 제작 시:

1. **correct_output은 실제 서비스 출력처럼** 쓴다 — 페르소나(adult) 눈높이 설명 2문장,
   조항 원문 문구를 인용하는 risk_evidence, 그 조항에 특정된 check_questions 1~2개.
   표본: `hldcc_20` (data/anchor_pairs.json 첫 항목).
2. **금지**: 라벨 메모 복붙("~문제가 있는 것으로 판단됩니다" 템플릿), 내부 id 참조
   ("id=2358과 대조"), 범용 질문("이 조항이 실제로 적용될 경우..."), 조항 원문에 없는
   법령·판례 번호를 explanation에 직접 노출(근거 요약은 risk_evidence에 자연문으로).
3. **wrong_output**은 기존 관례대로 한 줄 단정체(예: "통상적이고 문제없는 조항입니다").
   단, 재실행에서 정답 일치율이 다시 95%+ 천장에 붙으면 "미묘하게 틀린" 오답형
   (risk_type만 오분류, 그럴듯한 근거 인용)으로 난도 상향 검토.
4. **중복 검사**: 제작 전 `data/anchor_pairs.json`의 id·조항 텍스트와,
   `data/real_clause_labels.csv`의 출처 사건번호를 대조. 같은 사건의 문구 변형은 1건만.
5. Test 셋 확장분(+13)은 **앵커쌍으로 만들지 않는다** — Test는 held-out 원칙 유지,
   앵커쌍 소스와 사건이 겹치면 어느 한쪽에서 제외.
