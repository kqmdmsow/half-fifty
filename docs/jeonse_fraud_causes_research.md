# 전세사기 실제 발생 원인 리서치 — 조항 탐지의 스코프 한계 확인

> 교수님 피드백("특정 조항이 문제되어 전세사기가 나기도 하지만 대부분의 범죄는 다른 것 때문에
> 발생한다") 검증을 위한 리서치. 결론: **피드백이 데이터로 뒷받침됨** — 계약서 조항 탐지는
> "사기 예측"이 아니라 "이미 발생한 구조 위에서 피해를 가중/은폐하는 신호 탐지"로 스코프를
> 명확히 하는 게 맞다.

## 1. 실제 전세사기의 지배적 원인 (계약서 조항과 무관)

| 유형 | 메커니즘 | 대표 사례 |
|---|---|---|
| **무자본 갭투자** | 자기자본 없이 세입자 보증금으로 주택 매입 — 보증금이 곧 매입자금 | 인천 미추홀구 '건축왕'(730세대, 564억), 강서구 '세모녀'(355명, 800억, 12채→524채 확장) |
| **깡통전세/신축빌라 시세조작** | 시세 파악 어려운 신축빌라 특성 악용, 분양가·매매가 부풀려 그보다 높은 전세금 책정(전세가율 100%+) | 미추홀·동탄 사건 공통 패턴 |
| **대항력 공백 악용** | 전입신고 익일 0시 대항력 발생 전까지의 공백을 이용해 소유권/근저당 변경 | 계약 자체가 정상이어도 계약 **이후** 등기 변동으로 발생 |
| **신탁부동산 사기** | 소유권이 수탁자에게 있는데 원소유자(위탁자)가 무권한 임대차 계약 체결 | `data/real_labels_lbox_extension.md` id=2488/62108과 직결 |
| **이중계약/중개사 결탁** | 무자격·결탁 중개업자가 양쪽에 다른 내용 고지, 배당순위 허위 안내 | — |
| **저금리·정책 요인** | 2010년대 저금리로 전세가 급등, 비아파트 전세시장 임대인 우위화 | 학계 지적(대검찰청은 언급 안 함) |

대검찰청 중간수사결과는 원인을 **금융시스템 투명성 부족·규제 사각지대**로 지목하며, 계약서
조항은 원인으로 언급조차 하지 않음.

## 2. 계약서에서 "보이는" 부분 vs "안 보이는" 부분

**대부분(체감 70~80% 이상)은 계약서 문구 자체와 무관.** 임대인의 재무상태(다주택·부채),
시세조작, 계약 이후 등기 변동, 신탁 관계, 이중계약 여부는 조항을 아무리 정교하게 읽어도
드러나지 않음 — 등기부등본·전입세대열람·국세완납증명 등 **계약서 외부 자료**로만 확인 가능.

계약서에서 감지 가능한 건 제한적:
1. 신탁부동산인데 이를 숨기고 임대인이 직접 계약하는 경우, 특약사항의 신탁 고지 누락이 단서가 될 수 있음
2. 대항력 발생 공백을 노리는 의도가 "잔금일 이후 권리관계 유지 특약" 부재로 나타날 수 있음
3. 우리가 찾은 불공정 특약("수리비용 전액 임차인 부담", "갱신청구권 포기", "신탁 고지하며 책임 면제")은 **사기의 결과를 회피/전가하려는 부수적 장치**로 나타나지만, 사기 발생 자체의 1차 원인은 아님

## 3. 결론 — 프로젝트 스코프 재정의 필요

조항 탐지는 여전히 유효하지만, **"이 계약이 전세사기 위험이 큰가"를 예측하는 도구가 아니라
"계약서에 나타난 불공정/위험 신호를 놓치지 않게 돕는 도구"**로 스코프를 명확히 하는 게
데이터에 부합함. 진짜 사기 위험을 알려주려면 등기부등본·실거래가 데이터 결합이 필요한데,
이는 조항 분석과는 다른 종류의 작업임 (4절 참고).

## 4. 확장 가능성 검토 (2026-07-26)

유형별로 "지금 파이프라인(조항 텍스트 분석)으로 확장 가능한가"를 따로 평가함 — 뭉뚱그려서
"다 잡자"고 하면 안 되고, 유형마다 필요한 게 완전히 다르기 때문.

| 유형 | 조항 텍스트만으로 감지 가능? | 필요한 것 | 비용 |
|---|---|---|---|
| 신탁부동산 사기 | **부분적으로 가능** | risk_type 정식 채택만 하면 됨 — 이미 실증 근거 있음 | **매우 낮음** |
| 대항력 공백 악용 | 불가능(계약 이후 발생) — 다만 "확인하라"는 조언은 가능 | check_questions에 고정 체크리스트 추가 (조항 내용과 무관하게 항상 노출) | **낮음** (프롬프트만) |
| 깡통전세/시세조작 | 부분적 가능 — 주소+보증금이 있으면 외부 시세와 대조 가능 | 국토교통부 실거래가 공개시스템 API(무료 공개) 연동 | **중간~높음** (신규 백엔드 기능) |
| 무자본 갭투자 | 불가능 — 임대인의 다른 소유 부동산 정보 필요 | 등기부등본 파싱 또는 다주택 여부 조회 API | **높음** (신규 기능, 유료 API 가능성) |
| 이중계약/중개사 결탁 | 거의 불가능 — 타 계약 대조나 중개사 자격조회 필요 | 한국공인중개사협회 자격조회 연동 | **중간** |

### 우선순위 제안

- **바로 할 수 있는 것 (조항분석 파이프라인 그대로, 스코프 확장 아님)**: 신탁관계 risk_type 정식 채택, 대항력 공백/실거래가 확인 체크리스트를 check_questions에 고정 항목으로 추가 — **✅ 2026-07-26 구현 완료**. `agent/src/prompts/analysis.txt`·`baseline.txt`에 6번째 risk_type("신탁관계·소유권 불안정 고지") 추가, `agent/src/nodes/analysis.py`에 결정적(비-LLM) 고정 체크리스트 항목(`STRUCTURAL_RISK_CLAUSE_ID`)을 Ours 파이프라인에만 추가(Baseline과의 비교 가치를 위해 Baseline에는 미적용). `eval.py`의 리콜/오탐 집계·조항단위 정밀도 계산에서는 이 항목을 제외하도록 처리해 기존 지표가 깨지지 않게 함
- **진짜 스코프 확장인 것 (백엔드 신규 기능, 외부 API 연동)**: 실거래가 API 연동한 전세가율 자동 계산, 등기부등본 업로드·파싱, 중개사 자격조회 — **미착수, 팀/교수님과 스코프 논의 필요**

**주의**: 교수님이 이미 "지금은 시스템을 더 완성할 때가 아니라 검증할 때"라고 명시적으로
피드백했음(`docs/next_steps.md` 우선순위 4 "백엔드 인프라 후순위" 참고). 외부 API 연동류는
정확히 "시스템 완성"에 해당하는 작업이라 이 피드백과 충돌할 수 있음 — **팀/교수님과 스코프
확장 여부를 먼저 논의하고 진행하는 게 맞음.** 반면 risk_type 채택이나 check_questions
체크리스트 추가는 기존 파이프라인 안에서의 보강이라 이 피드백과 충돌하지 않음.
