# 검수 스프린트 4 — 금융 우선 12개 배치, 160건 중 5건 통과 (골든셋 4행 반영)

> 절차는 `docs/review_sprint3_log.md`와 동일 원칙: **제작 컨텍스트와 분리된 검수 컨텍스트**가 판례 원문 XML을 재대조하며 반박을 시도한다. 이번 스프린트는 **Claude Fable 5가 Claude Code 세션에서 직접 검수**했다 — API 크레딧 미사용(무료 제공자 경로 아님, 별도 배치 세션 12개로 컨텍스트 분리). 원문 접근 실패(보류 사유)는 12개 배치 전체에서 0건이었다.

## 대상 범위

- 3차 스윕 스테이징 전체 미검수 **1,558건** 중 금융 키워드 우선 12개 배치 = **160건 판정** (판정 후 남은 미검수 **1,398건**)
- 대상 파일(11개): 기한이익상실 19 · 여신거래약정 11 · 대출약정 10 · 근저당권설정 3 · 포괄근보증 4 · 연대보증 4 · 중도상환수수료 22 · 연체이자 23 · 수수료약정 32 · 신용카드약관 8 · 보험약관 24

**결과: {'기각': 142, '자동기각': 13, '수정승인': 5} · 통과율 5/160 = 3.1%** (스프린트 3 실측 8%, 3차 스윕 API 후보 예상 8~12%보다 낮음 — 판례 전문 검색형 금융 키워드가 무관 사건·법령 인용을 대량으로 끌어온 것이 주원인)

> `split`은 전부 `train`으로 넣었다. **held-out(test) 배정은 사람이 정한다** — 자동으로 test에 넣으면 공식 수치의 의미가 사라진다. 같은 사건의 조항은 같은 split(누수 차단): 2023나20705 신규 1행은 sprint3 승인 2행과 같은 train.
