# 조목조목 (half-fifty)

**금융 취약계층을 위한 AI 계약·약관 위험 안내 서비스** — 계약서를 '조목조목' 따져 준다는 뜻.
2026 전기 졸업과제 · 2026 금융 AI Challenge 1차 제출 완료(2026-09-07, 심사 9/7~9/11)

**배포**: https://halffifty.onrender.com (계정 없이 전 기능 사용 가능, 데모 샘플 10종 원클릭)

> 계약서의 정보 비대칭 때문에, 위험한 조항인 줄 모르고 서명해서 실질 피해를 입는
> 문제를 풉니다. 계약서를 올리면 조항 단위로 **① 위험 판정 ② 눈높이 설명
> ③ 서명 전에 해야 할 확인 행동**을 제시합니다. 판정 근거는 정부·법원이 실제로
> 판단한 사례(골든데이터셋)로 검증합니다.

## 주요 기능

- **조항 단위 위험 판정** — 약관규제법 조문에 대응하는 위험 유형 10종으로 판정하고,
  판정 근거 문구를 원문에서 직접 인용합니다.
- **행동 가이드** — 위험 조항마다 협상 문구와 구제기관(분쟁조정·상담 창구) 안내를
  붙여서, 탐지에서 행동까지 이어지도록 합니다.
- **페르소나 적응** — 판정은 그대로 두고 설명만 눈높이에 맞게 재작성합니다.
  판정 불변은 코드 구조로 보장되며 실측으로도 재확인했습니다.
- **안심의 근거** — 위험만 찾지 않습니다. 안전 판정 조항에도 "괜찮다고 본 근거"를
  함께 보여줍니다(사람 평가에서 일반인 다수가 안전 조항조차 불안해한다는 관찰 반영).
- **설명 대조 검증** — 판매자·중개인의 상담 설명(녹취 음성 또는 텍스트)을 계약서와
  대조해, 계약서에는 있는데 설명에서 빠진 위험 조항을 찾아냅니다.
- **안전장치** — 프롬프트 인젝션 6층 방어, 업로드 파일 검증, Judge 품질 게이트
  (점수 미달 시 재실행)를 갖췄습니다.
- 그 외: 화면 16개 언어·눈높이 설명 4개 언어(한·영·중·베트남어), 교육 챗봇, 로그인·
  분석 결과 계정 보관(영지식), 데모 샘플 10종(AI 조작 방어 체험 2종 포함) 사전 분석
  캐시 즉시 결과, 전세 위험 계산기, 음성 낭독·음성 명령·점자용 텍스트 다운로드.

## 아키텍처

```
프론트(5173) → 백엔드(8080) → 에이전트(8000)
                                └─ Parser → Domain → Analysis → Persona → Judge
                                                        ↑ 점수 미달 시 최대 2회 재실행 ┘
```

Domain은 문서 유형(주택/상가 임대차, 보험, 대출 등)을 1회 판별해 Analysis의
모든 조항 판정에 주입합니다 — 같은 문언도 유형에 따라 판정이 갈리기 때문입니다.
5단계 파이프라인은 단일 LLM 호출(Baseline) 대비 우위를 실측으로 비교·검증합니다
(`docs/eval_baseline_vs_ours.md` 계열).

```
half-fifty/
├── agent/      # Python + LangGraph 5단계 파이프라인 (담당: 최민제)
├── backend/    # Java Spring Boot API 서버 (담당: 전동훈)
├── frontend/   # React + TypeScript + TailwindCSS (담당: 김민찬)
├── data/       # 골든데이터셋·앵커쌍 (hldcc·LBox·AI Hub·금감원·법제처 실측 라벨)
└── docs/       # 실험 리포트, 검증 설계, 제출 문서, 회의록
```

## 검증 — 핵심 수치

교수님 중간 피드백("시스템 완성보다, 정말 도움이 되는지 **검증**부터")에 따라
검증 인프라를 먼저 구축했습니다. **모든 대외 수치의 단일 출처는
`docs/공식수치.md`입니다.** 아래 표는 그 요약이며, 각 수치의 근거 실험 문서
경로도 그 문서에 정리되어 있습니다.

| 무엇을 검증했는가 | 결과 |
|---|---|
| 공식 Test 40건 (held-out, 정부·법원 판정 기반) | 전체 입력 기준 정확도 72.5% (29/40) · P 0.71 / R 0.91 / F1 0.80 |
| A등급 27건 (정부·법원이 실제로 판정한 사례만) | **리콜 1.00** (위험 조항 놓침 0건) |
| 도메인 전이 — 금융 라벨 확정 16건 | 정확도 0.75 · 리콜 1.00 (임대차용 프롬프트를 무수정 적용) |
| LLM Judge 신뢰도 — 4개 모델 패밀리 × 앵커 40쌍 | clarity·risk_coverage·actionability 100%, faithfulness 97% |
| 정상 계약서 94조항 (표준 양식 5문서) | '위험' 오탐 0건 |
| 적대적 벤치마크 125건 (인젝션 공격 7계열) | 화면 노출 관통 0건 (모델 판정 기준 0.8%, 안전장치가 차단) |
| 페르소나 적응 24건 | 판정 불변 24/24 · 문장 길이 −31% · 전문용어 −52% |
| **사람 평가 — 일반인 33명 블라인드** (#162) | 페르소나 설명 선호 57.8% (p=0.025, 8문항 중 7문항 방향 일치) · 판정 과제에서 시스템 gold 일치 71.4% > 일반인 평균 61.0% · 결과: `docs/human_eval_results.md` |

- **골든데이터셋 211행** (`data/real_clause_labels*.csv`): 공식 Test 40 ·
  임대차 확장 34 · 금융 전이 32 · 스프린트 3~11 수집분 101(전부 train) 등.
  세트별 구성과 split 분포는 `docs/공식수치.md` §6에 있습니다.
- 수집 파이프라인: 키워드 필터 → 판결문·결정서 원문 정독(라벨링 에이전트) →
  **독립 적대적 검수**(별도 에이전트가 원문 재대조·반박 시도) → 통과분만 반영.
  기각 사유는 전부 문서화합니다(`docs/review_sprint*.md` 계열).
- 오염 방지 원칙: train/val은 자유 반복(프롬프트 튜닝용), **Test는 절대 보지 않고
  개선 확정 시 1회만** 실행합니다. 같은 사건은 같은 split에 둬서 누수를 차단합니다.
- 채점자 검증(RQ6): "프롬프트를 고쳤더니 좋아졌다"를 말하기 전에 채점자(LLM
  Judge)부터 4개 모델 패밀리 교차검증으로 확인했습니다 —
  `docs/eval_pairwise_judge_family_round2.md`.
